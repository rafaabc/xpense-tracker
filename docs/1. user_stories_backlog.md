# User Stories

---

## Epoch 1: Authentication & Identity

### US-01: User Registration with Google

**As a** new user,
**I want to** create an account using my Google credentials,
**So that** I can securely access the expense tracker without managing a separate password.

**Acceptance Criteria:**
- [ ] AC1: A "Sign in with Google" button is displayed prominently on the landing/registration page.
- [ ] AC2: Clicking the button initiates the Google OAuth consent flow.
- [ ] AC3: On first-time successful authentication, a new user profile is created, linked to the user's unique Google identity.
- [ ] AC4: After account creation, the user is taken to the Dashboard, which is empty and ready for setup (no expenses, groups, or subcategories yet).
- [ ] AC5: If the Google account used already has an existing profile, no duplicate is created and the user is signed in normally (see US-02).

**Business Rules:**
- BR1: Authentication is strictly exclusive to Google OAuth.
- BR2: Duplicate accounts for the same Google identity are strictly forbidden — the Google identity is the unique key.

---

### US-02: User Login with Google

**As a** registered user,
**I want to** log in using my Google account,
**So that** I can access my personal expense data securely.

**Acceptance Criteria:**
- [ ] AC1: Clicking "Sign in with Google" initiates the Google OAuth flow and, on success, establishes an authenticated session for the user.
- [ ] AC2: The session persists across browser instances until an explicit "Sign Out" occurs.
- [ ] AC3: The user is taken to the Dashboard, showing their own data.
- [ ] AC4: A "Sign Out" action is available and ends the session immediately.
- [ ] AC5: If Google authentication fails or is revoked, the user is redirected to the login page with an appropriate error message.

**Business Rules:**
- BR1: Unauthenticated traffic hitting any internal application route must instantly redirect to the login page (enforced globally, not only at the login entry point).

## Epoch 2: Structural Cadastres & Global Config

### US-05: Configure Preferred Currency

**As a** registered user,
**I want to** set my preferred currency,
**So that** all expenses are displayed in the currency I use day-to-day.

**Acceptance Criteria:**
- [ ] AC1: The user can select a currency from a supported list (DKK and BRL) in account settings.
- [ ] AC2: The default currency for new accounts is DKK.
- [ ] AC3: Once selected, every UI component rendering financial figures (amounts, summaries, charts) immediately updates to display the chosen currency symbol.

**Business Rules:**
- BR1: This is a cosmetic display setting only — no currency conversion is applied; raw stored decimal values are never mutated based on this preference.

---

### US-06: Manage Expense Groups

**As a** user,
**I want to** create, edit, and delete top-level expense groups,
**So that** I can structure my budget according to my spreadsheet design (e.g., Casa, Familiar, Transportes, Extras).

**Acceptance Criteria:**
- [ ] AC1: The user can create a new top-level Group by providing a name.
- [ ] AC2: The user can rename an existing Group.
- [ ] AC3: Group names must be unique (case-insensitive) for the user.
- [ ] AC4: The user can delete a Group via an explicit confirmation modal.
- [ ] AC5: If the Group contains Subcategories, the confirmation modal warns that all nested Subcategories and their associated expense records will be permanently deleted.
- [ ] AC6: Confirming deletion permanently removes the Group, all its Subcategories, and all expense records tied to those Subcategories.

**Business Rules:**
- BR1: Deletion is a cascading hard-delete — there is no restriction based on existing linked expenses.

---

### US-07: Manage Expense Subcategories

**As a** user,
**I want to** manage granular subcategories nested within groups,
**So that** I can log targeted costs (e.g., Rental, Supermarket, Fuel).

**Acceptance Criteria:**
- [ ] AC1: The user can create a new Subcategory by providing a name and selecting exactly one parent Group.
- [ ] AC2: The user can rename an existing Subcategory.
- [ ] AC3: Subcategory names must be unique (case-insensitive) within the boundaries of their parent Group.
- [ ] AC4: The user can delete a Subcategory via an explicit confirmation modal.
- [ ] AC5: If the Subcategory has expense records tied to it, the confirmation modal warns that all associated expenses will be permanently deleted.
- [ ] AC6: Confirming deletion permanently removes the Subcategory and all expense records tied to it.
- [ ] AC7: A Subcategory cannot be reassigned to a different parent Group after creation (must be deleted and recreated).

**Business Rules:**
- BR1: Deletion is a cascading hard-delete, consistent with US-06.

## Epoch 3: Core Financial Transactions (CRUD)

### US-10: Create Expense

**As a** user,
**I want to** log an expense,
**So that** I can record my spending history.

**Acceptance Criteria:**
- [ ] AC1: The form requires Amount, a Subcategory picker (grouped visually under parent Groups), and a Date.
- [ ] AC2: Date defaults to today's date; future dates are rejected with a validation error.
- [ ] AC3: Past dates of any age are accepted (to support historical data migration and backdated entries).
- [ ] AC4: Amount must be a positive decimal strictly greater than 0.00, with up to 2 decimal places; non-numeric or out-of-range input is rejected with a validation error.
- [ ] AC5: On successful save, the user receives confirmation and the expense appears in the expense list (US-11).

**Business Rules:**
- BR1: Amount must be a positive numerical value strictly greater than zero (`> 0.00`).

---

### US-11: View Expenses

**As a** user,
**I want to** see a list of my transactions,
**So that** I can audit my history.

**Acceptance Criteria:**
- [ ] AC1: The list renders the user's expenses.
- [ ] AC2: Each row displays Amount (formatted per the user's currency preference), Group, Subcategory, and Date.
- [ ] AC3: Default sort order is date-descending (most recent first).
- [ ] AC4: The user can filter the list by date range, Group, and/or Subcategory.
- [ ] AC5: If no expenses exist for the active filter combination, an empty state message is displayed (not a blank screen or error).
- [ ] AC6: The list is paginated or virtualized when the number of entries is large, to maintain performance.

---

### US-12: Edit Expense

**As a** user,
**I want to** modify an expense entry,
**So that** I can fix mistakes.

**Acceptance Criteria:**
- [ ] AC1: Selecting an expense opens the transaction form pre-populated with its current Amount, Subcategory, and Date values.
- [ ] AC2: The same validation rules from US-10 apply: Amount must be `> 0.00` with up to 2 decimals, and Date cannot be in the future.
- [ ] AC3: Saving changes updates the existing record in place (same identity) rather than creating a new one.
- [ ] AC4: On successful save, the user receives confirmation and the updated values are immediately reflected in the expense list (US-11).
- [ ] AC5: A user can only edit their own expense records.

**Business Rules:**
- BR1: Cross-tenant protection enforces that users can only edit their own data.

---

### US-13: Delete Expense

**As a** user,
**I want to** delete a transaction entry,
**So that** I can remove accidental records.

**Acceptance Criteria:**
- [ ] AC1: An explicit confirmation modal is shown before any deletion proceeds.
- [ ] AC2: Confirming the modal permanently removes the record — no soft-delete/recovery is available.
- [ ] AC3: Canceling the modal leaves the record untouched and closes the dialog.
- [ ] AC4: On successful deletion, the user receives confirmation and the expense list (US-11) immediately refreshes to no longer show the deleted entry.
- [ ] AC5: A user can only delete their own expense records.

**Business Rules:**
- BR1: Deletion is permanent (hard delete) — no soft-delete flag or trash/restore mechanism exists.

## Epoch 4: Automation & Recurrence Engines

### US-08: Create Recurring Expense

**As a** user,
**I want to** set up automatic expenses (like Rent),
**So that** I don't manually type repetitive items.

**Acceptance Criteria:**
- [ ] AC1: Setup requires Amount, Subcategory, Start Date, Interval (Monthly, Every 6 Months, Every 12 Months — or equivalent configurable cadence), and a day-of-month execution rule.
- [ ] AC2: A standard expense entry is automatically created on the configured day for each cycle.
- [ ] AC3: If the configured day-of-month does not exist in a given month (e.g., day 31 in a 30-day month), the entry is generated on the last day of that month instead.
- [ ] AC4: The user can view a list of all active recurring templates, showing Amount, Subcategory, Interval, and next execution date.
- [ ] AC5: The user can deactivate/delete a recurring template; doing so stops future generation but does not affect already-generated past expense entries.

**Business Rules:**
- BR1: Editing a recurring schedule template (amount, interval, etc.) applies to future generations only; past entries remain untouched.

---

### US-09: Annual Recurring Expense Renewal

**As a** user,
**I want to** be prompted to renew/review my fixed costs at the end of the year,
**So that** price adjustments (like subscription changes) are captured accurately.

**Acceptance Criteria:**
- [ ] AC1: On the anniversary of each recurring template's Start Date (i.e., 12 months after creation or last renewal), an in-app review banner/notification is triggered for that template.
- [ ] AC2: The banner displays the template's current Amount, Subcategory, and Interval, and offers options to "Confirm (no change)" or "Update value".
- [ ] AC3: Confirming with the same value extends the template's active period by another 12 months without creating a new template.
- [ ] AC4: Entering a new value deprecates the old template (stops it from generating further entries from that point forward) and creates a new successor template with the updated value, preserving the same Interval and execution day.
- [ ] AC5: The user can dismiss/snooze the banner without acting; it reappears on subsequent logins until addressed.
- [ ] AC6: If left unacted upon indefinitely, the original template continues generating entries at the old price (no gap in tracking).

**Business Rules:**
- BR1: An unacted-upon renewal does not block or pause recurring entry generation — entries continue at the old price until the user acts.

## Epoch 5: Analytical Summaries

### US-14: View Monthly Summary

**As a** user,
**I want to** review monthly spend statistics,
**So that** I can see total volume and percentage shares per Group.

**Acceptance Criteria:**
- [ ] AC1: The user can select a month and year to view (defaulting to the current month/year).
- [ ] AC2: The summary aggregates the total spend across all expenses for the selected month/year.
- [ ] AC3: Each Group's subtotal is displayed alongside its percentage share of the overall monthly total (e.g., Casa 40%, Familiar 15%).
- [ ] AC4: Percentage shares across all Groups sum to 100% (accounting for rounding) when the monthly total is greater than zero.
- [ ] AC5: If the monthly total is zero (no expenses recorded), the view displays a zero/empty state instead of attempting percentage calculations (avoiding division by zero).

---

### US-15: View Annual Summary

**As a** user,
**I want to** see yearly distributions and month-over-month trend charts,
**So that** I can track my historical execution over time.

**Acceptance Criteria:**
- [ ] AC1: The user can select a year to view, limited to years for which the user has at least one recorded expense.
- [ ] AC2: For a completed past year, the summary displays totals and per-Group averages calculated by dividing each Group's annual total by 12.
- [ ] AC3: For the current (in-progress) year, per-Group averages are calculated by dividing each Group's total by the number of elapsed months (months with at least one day passed so far), not by 12.
- [ ] AC4: A cross-sectional chronological matrix (Groups × Months) is generated, showing each Group's subtotal for each month of the selected year, for comparative trend analysis.
- [ ] AC5: Months with no recorded expenses display as zero in the matrix (not blank/null), and do not cause errors in average calculations.
- [ ] AC6: A month-over-month trend chart visualizes the overall total spend across the 12 (or elapsed) months of the selected year.

**Business Rules:**
- BR1: Annual averages divide by 12 for completed years and by the count of elapsed months for the current year — never by 12 for an in-progress year.
